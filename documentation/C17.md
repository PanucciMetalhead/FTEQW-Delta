# C17 modernization

C17 is the current language baseline. The migration was developed on
`dev/c17` against the pre-migration master commit
`bf8df44cd60b8a27e39d97cf3c4a1332e70a045e`.
The repository owner approved merging after native macOS Metal checks and
successful Windows, macOS and Linux GCC/Clang CI builds and regression tests.
Native Windows/Linux Vulkan playtests were unavailable; users can report
platform-specific problems through GitHub issues.

## Language and diagnostic policy

CMake 3.21+ requires C17 for every C target and disables GNU language mode.
The C++ IQM tool and external C++ dependencies keep their own language settings.
Operating-system APIs and explicit compiler attributes are still dependencies;
this is not a claim that every legacy source is strictly ISO-only C.
Linux enables POSIX 2008 and the default glibc APIs explicitly, preserving the
API visibility previously supplied by GNU C mode.

`cmake/FTECompilerPolicy.cmake` applies the same diagnostics in release and debug
builds. GCC/Clang reject missing declarations, implicit integer types,
incompatible pointer types, missing returns, unsafe format-only calls, and
non-prototype/old-style function declarations. MSVC rejects undeclared functions,
excessive arguments, and missing returns. Broad warnings remain visible without
turning every inherited warning into a build failure.

- `FTE_WERROR=ON`: make all warnings fatal (`-Werror` or `/WX`). Not yet a
  supported clean build across the whole legacy tree.
- `FTE_EXTRA_WARNINGS=ON`: audit conversions, additional format checks,
  extensions and alignment on GCC/Clang, or use `/W4` on MSVC. This intentionally
  reports a substantial legacy backlog; it is not the default build policy.
- `FTE_SANITIZERS=ON`: instrument a single-configuration Debug build with
  AddressSanitizer and UndefinedBehaviorSanitizer on Linux/macOS. Undefined
  behavior is fatal, even when `UBSAN_OPTIONS` is not set.

Byte-string pointer-sign warnings and foreign compiler pragmas retain explicit
exceptions. No fast-math, floating-point precision, movement constants, physics
rules, protocol definitions, or saved-game formats are changed by the migration.

## Compatibility repairs

- QTV endian helpers replace GNU statement expressions and `typeof` with
  fixed-width C functions. They preserve disk bytes, signed leaf sentinels and
  single evaluation of arguments, avoiding signed shift overflow.
- QuakeC chain field indices use `offsetof`, with compile-time slot-size and
  alignment checks, instead of subtracting null pointers.
- Macro expansion avoids null-pointer subtraction and zero-byte copies from
  null buffers. Comment accumulation guards the same empty-buffer case. These
  were actual failures found by the Linux sanitizer fixtures.
- Compiler compression/PAK placeholders are initialized before writing. The
  completed headers are still rewritten in their original formats.
- Compiler uninitialized-variable analysis uses numeric byte ranges, including
  not-yet-allocated symbols, instead of arithmetic on null pointers or ordered
  comparisons between unrelated allocations.
- Client-only SDL startup excludes the dedicated-server path. CSQC/menu
  coroutines no longer require a server VM; `fork` reads its own VM's arguments.
  Server entity generation checks retain their existing behavior.
- QTV detects Unix using the reserved platform macro available in ISO C mode.
  Windows compiler keyword comparisons use the existing portable wrapper;
  CMake escapes installation paths containing spaces. Windows server builds
  link their native thread implementation and system libraries. SDL pipe output
  uses the Windows API, debugger waits use the existing sleep abstraction, and
  Windows SDL3 builds use the native home-directory helpers. Standard format
  headers and optional zlib guards also cover the standalone VM and QTV.
  A dead reference after
  the Quake 3 plugin's unimplemented trap return is removed to let MSVC link it.

## Data-free checks

```sh
cmake -S . -B build/c17 -DCMAKE_BUILD_TYPE=Release \
  -DFTE_TOOL_QCVM=ON -DFTE_ENGINE_CLIENT_ONLY=ON \
  -DFTE_TOOL_QCCGUI=OFF -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build/c17 --parallel
ctest --test-dir build/c17 -C Release --output-on-failure
python3 tools/c17_compat.py --build build/c17 --out build/c17-compat
python3 tools/network_transport_tests.py --out build/c17-network-tests
```

`c17_compat.py` requires GCC/Clang compilation commands. It checks every C
translation unit uses `-std=c17`, exercises endian helpers with 100,000 patterns
under sanitizers, and compares assembly from GNU C11 and ISO C17 with identical
compiler and optimization settings for `pmove.c`, `sv_phys.c`, `world.c`, and
`mathlib.c`. Those sources must also match `--baseline-ref` (default `master`).
LTO is disabled for this assembly comparison only. It does not replace full
runtime gameplay tests. CI uses `--baseline-ref HEAD` to test dialect effects;
the original local validation used pre-migration master to also guard against
source changes. After merging, pass that baseline revision explicitly with
`--baseline-ref bf8df44cd60b8a27e39d97cf3c4a1332e70a045e` to retain the original
source-change guard.

To compare compiler output against a saved baseline binary:

```sh
python3 tools/qcc_regression.py --compiler build/c17/fteqcc \
  --vm build/c17/qcvm --baseline /path/to/master/fteqcc \
  --out build/c17-qcc-tests
```

The compiler fixture compares bytecode at optimization levels 0–3, executes it
in the VM, and verifies help, diagnostics, and warning controls. CTest runs this
fixture when both `fteqcc` and `qcvm` are built; byte-for-byte baseline comparison
requires the explicit baseline argument above.

```sh
cmake -S . -B build/c17-sanitize -DCMAKE_BUILD_TYPE=Debug \
  -DFTE_SANITIZERS=ON -DFTE_TOOL_QCVM=ON -DFTE_TOOL_QCCGUI=OFF
cmake --build build/c17-sanitize --target fteqw fteqw-sv fteqcc qcvm c17-endian-check --parallel
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build/c17-sanitize --output-on-failure
```

With Python and the corresponding targets present, sanitizer CTest also runs
`parser-sanitizers` and `engine-sanitizer-smoke`. These exercise real packet,
text, numeric and Q3 escape parsers and actual headless server startup without
game data. See [SafetyChecks.md](SafetyChecks.md) for the full build command,
coverage, warning inventory and remaining work.

Leak detection is disabled for this targeted engine/compiler/VM check because it is
not a compiler shutdown-ownership audit. Address and undefined-behavior checks
remain enabled. A successful fixture does not establish whole-engine sanitizer
cleanliness across every mod and optional subsystem.

## Local validation record

On macOS with the native Metal backend, the C17 branch passed:

- All default CMake targets, including full/client-only/server engines, tools
  and available plugins; release and ASan/UBSan compiler/VM fixtures.
- Assembly equivalence for movement, server physics, world and math against
  the GNU C11 baseline, with 498 C compilation commands using C17.
- Byte-for-byte compiler output at optimization levels 0–3. Compressed FTE
  output also matches the baseline in release and sanitized builds. The
  standalone `qcvm` build does not load compressed bytecode; its execution
  checks use the uncompressed fixtures.
- Full/client-only CSQC chain searches and zero-argument/delayed coroutines.
- Bidirectional exchange with pre-migration master of legacy, FTE text and binary saves,
  plus QuakeWorld demo playback.
- Lossy UDP/DTLS joining and reliable chat, malformed headers, datagram size
  limits and rejection of an incorrect certificate pin.
- Gamma, Panini, reflective liquids, custom textures, Arcane Dimensions and
  renderer restart checks. The Tears of the False God faithful benchmark at
  2940×1846 measured about 137 FPS with a paused scene and 278 FPS during the
  camera sweep. These measurements confirm healthy local performance; they
  do not establish a speedup from changing the C standard.

Native Vulkan playtests on Windows and Linux have not been performed. The
merge was approved with that limitation; hosted CI supplies build and data-free
test coverage for those platforms.
The extra-warning audit still reports a substantial inherited backlog.

## Game-data checks

Use isolated directories and owned game data with the renderer tools described
in [SDL3-GPU.md](SDL3-GPU.md). Test gamma, Panini, reflective liquids, custom
textures/skies, Arcane Dimensions and performance. Run local lossy UDP/DTLS
connections with `tools/network_integration.py`, explicitly selecting the C17
client and server. Verify saved-game exchange and demo playback against a saved baseline build.

The CSQC fixture exercises all four entity-chain operations with their default
field, then zero-argument and delayed coroutines in both full and client-only
engines. It opens native GPU windows and needs owned game data:

```sh
python3 tools/c17_csqc.py /path/to/Quake --build build/c17 \
  --out build/c17-csqc
```

For future changes, use Linux GCC/Clang, macOS Clang and Windows MSVC builds,
data-free and sanitizer fixtures, and available native backend playtests to
check movement, physics, mod behavior and file/network compatibility.
The GitHub workflow runs build and data-free checks on pushes to `master` and
`dev/c17`, and pull requests targeting master. Hosted build checks do not
provide native GPU playtests or access to the owner's Quake data.

The current warning cleanup and expanded sanitizer record are documented in
[SafetyChecks.md](SafetyChecks.md). Remaining conversion, initializer, formatted
output and extension warnings are follow-up audits. Address them in focused patches with their own behavior tests;
do not hide them with casts or change serialized structures merely to silence
the compiler.
